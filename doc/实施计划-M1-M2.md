# AgentOps 中控台实施方案（M1 + M2）

> 本文件是实施基准：配合 `doc/AgentOps中控台-需求设计文档.md` 使用。实施过程中每完成一个阶段在文末「实施进度」追加勾选记录，新会话可直接读取本文件续作。

依据 `doc/AgentOps中控台-需求设计文档.md` 实施，范围 **M1（MVP）+ M2**，后端 **Node 22 + Hono + better-sqlite3**，前端沿用现有 React + Vite + Tailwind 原型改造。与文档的两点偏差（已与操作员确认）：

- 指挥 agent 默认模型账号 = **Kimi Code**（文档默认 DeepSeek，操作员改为 Kimi Code；后端做成可配置，DeepSeek / Codex 可切换）。
- DeepSeek API Key 由操作员稍后自行放入 `~/.agentops`，代码实现完整读取/调用/降级链路，无 Key 时自动落演示模式。

---

## 一、总体结构

仓库根目录保持为前端工程，新增 `server/` 子工程（独立 `package.json`，互不干扰）：

```
AgentOps/
├─ src/                  # 前端（现有原型改造）
│  ├─ sections/          # 六大面板 + 新增 Commander 抽屉
│  ├─ store/             # 新增：单向数据流 store（WS → store → 组件）
│  ├─ api/               # 新增：REST 客户端 + WS 客户端（断线重连 + 全量对齐）
│  ├─ types/             # 新增：事件模型/领域类型（从 server 复制共享定义）
│  └─ data/mock.ts       # 降级为演示模式专用数据源（按文档口径修正）
├─ server/               # 新增：后端单进程模块化单体
│  ├─ src/core/          # 事件模型、内存聚合层、规则引擎（M2）
│  ├─ src/adapters/      # kimi / codex / deepseek-otel 适配器 + mock
│  ├─ src/quota/         # QuotaCollector（DeepSeek 真实 + Kimi/Codex mock）
│  ├─ src/commander/     # CommanderService（M2）
│  ├─ src/db/            # SQLite schema 与迁移
│  └─ package.json       # hono @hono/node-server @hono/node-ws better-sqlite3 tsx
└─ vite.config.ts        # 增加 /api 代理到 127.0.0.1:4711
```

端口：后端 `127.0.0.1:4711`，前端 dev `4712`（vite `server.port` + proxy）。

## 二、后端实施步骤（M1 → M2）

### 阶段 1：内核先行（文档 §13.1 提示的落地顺序）

1. `server/src/core/events.ts` — §7.1 统一事件模型类型（ULID 发 id，时间戳 ISO8601 带时区）；事件总线用 Node `EventEmitter`（明确不引外部 MQ）。
2. `server/src/core/aggregate.ts` — 内存物化视图：agents / tasks / accounts / alerts 当前态；启动时按 §8.1-A3 重建规则重放（仅 `agent.* / task.* / dag.* / approval.*` 生命周期事件参与重放；`quota.snapshot`、`command.*` 只取最新）。
3. `server/src/db/` — better-sqlite3，按 §9 建表（M1 建 `agents/tasks/events/accounts/quota_snapshots`，M2 加 `commands`，`dag_proposals` 表一并建好留给 M3）；全局任务 ID 发号器（`T-xxxx` 自增，`local_task_id` 映射）。
4. HTTP 层（Hono）：
   - `GET /api/state` 全量状态
   - `WS /api/stream`（`@hono/node-ws`）事件推送 `{type:"event", data: AgentEvent}`
   - `POST /api/hooks/:source`（kimi/codex/otel）hook 回调入口 → 适配器 `ingest()` → 总线
   - `POST /api/agents/:id/pause|resume`（M1 走适配器控制通道，无通道时返回只读提示）
5. **Hook 鉴权**（§7.1）：服务启动生成随机 token 写 `~/.agentops/hook-token`（Windows 下尽力设 ACL/权限位），所有 `/api/hooks/*` 校验 `X-AgentOps-Token` 头。
6. **密钥存储**（§8.2）：`~/.agentops/config.enc`，AES-256-GCM，主密钥为 `~/.agentops/master-key`（0600，启动时若无则生成随机 32 字节）；提供首次启动写入 DeepSeek Key 的引导命令 `npm run setup:key`；日志对 `Bearer`/`token` 值脱敏。

### 阶段 2：配额采集（M1 验收强制项）

7. `server/src/quota/collector.ts` — QuotaCollector 轮询 → 产出 `quota.snapshot` 事件 → 落库 + WS 推送；消耗速率用近 1h 快照最小二乘斜率（窗口型 %/h，余额型 ¥/h）。
8. **DeepSeek 真实接通**：`GET https://api.deepseek.com/user/balance`，60s 周期，解析总额/充值/赠送；无 Key 或请求失败 → 该账号自动降级 mock 并在事件中标注 `demo: true`。`GET /api/accounts/:id/quota?range=1h` 查历史。
9. **Kimi Code / Codex mock 适配器占位**（文档 M1 允许）：界面标注「演示数据」；采集器接口留好，真实接通（CLI `/usage`、`/status` 解析）为 M1 后跟进项，不在本次范围。

### 阶段 3：M2 后端

10. `server/src/core/rules.ts` — 规则引擎（配置化阈值）：窗口配额 ≤15% CRIT / ≤40% WARN；blocked 超 10min WARN；进入 waiting WARN；task.done OK；重置 <30min INFO。告警去重与自动恢复，产出告警对象进 `/api/state` + WS。
11. `server/src/commander/` — CommanderService：
    - 会话管理：按操作员单会话 + 每 agent 线程；历史落 `commands` 表。
    - LLM 后端抽象 `CommanderBackend`，两个实现：`kimi`（**默认**，子进程调 Kimi Code CLI 非交互模式）与 `deepseek`（OpenAI 兼容 HTTP API）；启动时探测 kimi CLI 是否可用，不可用自动降级 deepseek，再不行降级本地模板回复并标注。
    - 状态摘要注入（§FR-8）：仅新会话首轮与状态类问题时注入（在线 agent/任务/配额/未决告警，≤2k token），其余走滑动窗口。
    - `@agent` 转发降级链：默认走「CLI 非交互新会话」（kimi/codex 各一个转发实现，M2 用 mock 进程模拟亦可演示）；适配器无输入通道（deepseek-otel）→ 回复「该 agent 只读，无法对话」。
12. API：`POST /api/command`、`GET /api/command/history?limit=50`；回复经 WS 推 `command.reply`。

## 三、前端改造步骤（修正原型 + 接真实数据源）

1. **类型与 store**：`src/types/events.ts`（与后端事件模型对齐）、`src/store/appStore.ts`（轻量自实现 store：`useSyncExternalStore`，不引新依赖）；`src/api/client.ts`（REST + WS，断线指数退避重连，重连后拉 `/api/state` 全量对齐 —— §8.1-A4 单向数据流）。
2. **演示模式降级**：`/api/state` 不可达时自动切 mock 数据驱动，顶栏 `LIVE` 徽标变 `DEMO`（琥珀色），页脚标注「演示模式」。
3. **修正原型与文档的偏差**：
   - `src/data/mock.ts`：账号/agent 改为文档口径的三个来源（Kimi Code、ChatGPT/Codex、DeepSeek API），去掉 Claude/Gemini/Copilot 等出戏数据。
   - `src/sections/QuotaPanel.tsx`：**重构为双形态卡片**——窗口型（大号剩余% + 进度条 ≤40% 琥珀 ≤15% 红+「告急」+ 重置倒计时秒级走动 + 次级窗口并列 + %/h 速率）与余额型（大号 ¥ 余额 + 总额/充值/赠送细分 + ¥/h 速率 + 预计可用天数，**无倒计时**）；Codex 卡片按账号聚合并标注共享 agent 数；底部派单建议由后端规则给出（窗口型互比余量取最高，DeepSeek 兜底，不做跨形态换算）。
   - `src/sections/AgentFleet.tsx`：**M1 去掉进度条**（文档明确 CLI agent 无法自报真实进度），以状态 + 已运行时长（HH:MM:SS 实时走动）+ token/成本代替；新增「对话」按钮（唤起指挥台并预填 `@agent名`，只读来源置灰）；暂停/批准按钮改为调后端 API。
   - `src/sections/DagGraph.tsx`：节点/边改为由 `task.dispatch` 事件驱动实时增减，保留流动虚线动画与图例。
   - `src/sections/GanttChart.tsx`：数据来自 tasks 记录，时间窗可切换 48m / 3h / 24h，右缘 NOW 标线随真实时间。
   - `src/sections/Ticker.tsx`：内容由规则引擎告警驱动，悬停暂停。
   - `src/sections/MessageFeed.tsx`：由 `message.*` 事件驱动。
   - `src/pages/Home.tsx`：删除所有 setInterval 模拟逻辑，改为 store 订阅。
4. **新增指挥台（M2, FR-8）**：`src/sections/CommanderPanel.tsx` —— 右下悬浮雷达按钮唤起右侧抽屉（~380px）；面板头部显示当前对话对象及其模型/账号；消息按线程分组（指挥 agent 默认 / @agent）；历史从 `/api/command/history` 加载，刷新不丢；发送中/失败重发状态；`command.reply` 经 WS 实时到达。
5. **设计令牌与动效**：核对 `src/index.css` 与 §6 令牌一致；全部动效遵守 `prefers-reduced-motion`。

## 四、验证方式（对照 §12 验收）

- **M1**：① `npm run dev`（server + web 同时起），演示模式可见舰队与配额面板，倒计时/token 走动；② `curl -H "X-AgentOps-Token: ..." -X POST localhost:4711/api/hooks/kimi -d '{...task.progress...}'`，对应卡片 1 秒内更新；③ 放入 DeepSeek Key 后余额每 60s 落库，`/api/accounts/deepseek/quota` 可查历史；余额型卡片无倒计时、窗口型有。
- **M2**：模拟 `task.dispatch` 事件后 DAG 实时增减边；把 mock 配额压到 15% 以下触发 CRIT 上 ticker；指挥台发消息收到指挥 agent 回复；`@agent` 消息转发并回流，deepseek-otel 来源正确提示只读。
- 工程校验：`npm run build`（tsc + vite）与 `npm run lint` 通过；server 侧 `tsx` 启动无报错。

## 五、明确不做（本次范围外）

- M3 全部（编排提议确认流、HITL 审批回传、事中纠偏、Session 回放、周报）——但 `approval.*`/`dag.*` 事件类型、`dag_proposals` 表、DAG 组件预览态接口预留好。
- Kimi Code `/usage`、Codex `/status` 的真实配额解析（M1 后跟进项）。
- Docker / 外部 MQ / 云端同步（文档明确禁止或排除）。
